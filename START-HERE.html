  2. Install approved stable, final standard Python 3.15 if needed (alpha/beta/rc previews are refused). Double-click START-WINDOWS.cmd → 1 Setup/repair base. New installs prefer 3.15; existing working environments keep their actual displayed interpreter.
  3. Choose 2 Configure IDs: enter your real Discord User, Server and Application IDs. The wizard validates/saves nonsecret settings directly and shows the official authorization link if needed. No HTML download or JSON move is required. Discord authorization still needs your permission; this is not zero-config.
  4. Choose 3 Start bot; enter the token only at the hidden console prompt or via the process environment. Never put a token on this page, in JSON, chat, a URL or command arguments.
  5. Read and accept /farmer consent; select /farmer storage channel:#chosen-private accept:true. Run /farmer pull url:<your permitted link>. No reference means no model and no character identity claim. Approve only the exact displayed external image hosts if prompted.
  6. When complete, /farmer save job:<id> mode:collection stores results only in the selected private channel. Keep local originals/exports/receipts. The PC/console must remain running.

3 · Install the base, start, then pull a link

  1. Use standard CPython 3.11–3.15 (new base installs prefer 3.15) and the complete source from ViaticNovva/TechFarmer. Use menu 2 to save IDs locally; browser-exported JSON is only an advanced alternative.
  2. Double-click START-WINDOWS.cmd, choose 1 for base setup, 2 for IDs, then 3 to start. The base install uses your configured package index; no administrator request or proxy/DNS/policy workaround. Enter the token only at the hidden local console prompt, never in HTML, JSON, a URL or chat. Keep the PC running.
  3. Read /farmer consent, then accept with accept:true. Only collect material you own, licensed or have explicit permission to download/edit.
  4. Choose an existing private regular text channel: /farmer storage channel:#chosen-private accept:true. Public, news, thread, DM and foreign-server channels are refused. No channel permissions are changed.
  5. /farmer pull url:<your permitted link> collects native pages with no character identity claim and no model requirement. Poll /farmer status. If prompted, /farmer approve job:<id> displays exact external image hosts; its approval button is bound to that set.
  6. When complete: /farmer save job:<id> mode:collection. This stores results in the chosen channel, not the current channel. Repeat to continue bounded batches; receipts prevent blind resends.

Persistent channel messages/files are visible to everyone with channel access, including permitted roles/admins, and subject to Discord retention/limits—not owner-only privacy or a guaranteed permanent archive. Keep local originals/exports/receipts. Controls, errors and previews remain ephemeral. Native PNGs that exceed Discord's limit remain local, unchanged.

4 · Updating: stop → update → restart

/farmer version shows the installed version. /farmer update checks canonical GitHub only; it cannot execute Python or install from Discord.

First upgrade from an incomplete/older folder, or with only 3.15 and an old incompatible updater: stop all old bot windows, keep that folder as a backup, and obtain the full reviewed source in a new sibling folder. Copy nonsecret settings/data/exports/cache only into absent destinations; do not overwrite two populated data folders or copy old code over the new source. Use the new main menu to install the base and start; never copy or recreate a working old .venv silently. Schema 1/2 settings and compatible v0.2 jobs migrate with backups; incompatible legacy databases stay unchanged with an explicit NOT migrated notice. See README for the optional verified in-place updater bootstrap.

Complete v0.3/future updates: stop the bot, run UPDATE-WINDOWS.cmd (or new menu 4), close/reopen the menu, choose 1 for base setup/repair, then start and check /farmer version says 0.4.0. A v0.3 updater needs its existing 3.11/3.12 for that first step; v0.4 keeps the exact same managed source paths. Do not overwrite manifest-tracked updater files to bypass a mismatch. A process lock prevents concurrent bot/CLI/update work; the first upgrade requires local STOPPED confirmation because old bots had no lock. User settings/data/cache stay local. No branch/URL override, remote shell command or public backup host.

Read README and TESTING for exact support and executed-vs-unverified evidence. No live Discord login/post, native Windows run, model download, real comic artwork or third-party site compatibility was verified here.
